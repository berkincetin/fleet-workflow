## Notable issues resolved (symptom → root cause → fix)

- **Presidio's default config hung** trying to auto-download `en_core_web_lg` via spaCy's pip-based downloader → uv-managed venvs have no `pip` → explicitly configured `NlpEngineProvider` with `en_core_web_sm`, vendored as a direct-URL dependency instead of a runtime download.
- **Windows `ProactorEventLoop` + cached asyncpg connection pool** (`fleet_api.db._app_session_factory`, a process-wide `lru_cache`) doesn't tolerate reuse across separate `asyncio.run()` cycles / Starlette `TestClient`'s per-call event loop churn → `RuntimeError: Event loop is closed` on a second live test in the same session. Fixed by switching live tests to `httpx.ASGITransport` inside one `asyncio.run()` block and clearing the cache at the start of each test. Windows/TestClient-specific; production (uvicorn, one long-lived loop) is unaffected.
- **`Hit`/`Citation` design gap caught before wiring the live endpoint:** an integer `chunk_id` mirroring the `chunks` table's PK isn't known at Qdrant-upsert time (the PK is Postgres-assigned *after* the vector upsert in the current worker ordering) → switched to `chunk_ref: str` carrying `content_sha256` instead of reordering the 3.1 pipeline.
- **CORS 405 on preflight (found live while manually verifying 3.4):** `CORSMiddleware` was added *before* the other middleware, but Starlette wraps in reverse add-order (last-added = outermost) — CORS must run first to short-circuit OPTIONS. Moved it to be added last; regression-locked with 2 new integration tests.
- **`next@15.1.0` flagged CVE-2025-66478 on install** → upgraded to the latest 15.x patch (`15.5.20`), staying off a major-version jump mid-sprint.
- **`next-env.d.ts` (auto-generated) failed `eslint`** with a triple-slash-reference rule, which would block `make lint`/CI for anyone who'd run `next dev`/`next build` locally → added it to the ESLint ignore list (it's gitignored and regenerated by the framework itself, not code to fix).
- **bge-m3 (local embedding model) wasn't pulled** → asked the user before a multi-GB download rather than silently skipping live PII/local-lane verification or downloading unprompted; user chose to pull it for full live proof.

## Deviations / deferrals

- **"Hybrid retrieval (dense + keyword filter)"** is dense kNN narrowed by Qdrant's `MatchText` full-text filter, not sparse-vector (BM25/SPLADE) fusion — matches the literal task wording; true fusion needs a second named vector at ingest time, a larger change than scoped here.
- **No per-agent config table lookup yet** — `/v1/rag/query`'s caps come from the request (`top_k`), not a real per-agent `agents` table row; that wiring lands with the agent runtime in Sprint 4.
- **Collections API writes require `MANAGE_DEPT`**, but no seeded dev-realm Keycloak user holds a role matching `rbac.py`'s exact `dept_admin`/`platform_admin` strings (the realm seeds `admin`/`builder`/`approver`/`user`) — a pre-existing Sprint-1/2 gap, not introduced or fixed here, worked around via direct SQL for test/demo collection setup. Also affects Sprint 2's `MANAGE_PLATFORM`-gated `models_admin` router. Flagging for a future task.
- **No visual/pixel verification of the web UI** — no headless-browser tool was available in this environment; verification exercised the real HTTP contract (OIDC flow, uploads, polling target) instead. A styling-only regression that doesn't affect the HTTP contract would not have been caught.
- **shadcn/ui's CLI scaffold wasn't run** — a small hand-written Button/Card/Badge kit (same conventions: class-variance-authority + Radix + Tailwind) covers exactly what the Knowledge screens need.
- **Chat, My Approvals, Workflow catalog** (also under TRD §12 "End-user") are out of scope for 3.4 — task text names only Knowledge; Chat is Sprint 4 task 4.3.

## Cross-cutting rules honored

- **Rule 1** (LLM calls only via the gateway client): ingestion's OCR and query's embed/generate calls all go through `core.llm.client.LLMClient`; no provider SDK imported in `fleet_rag`.
- **Rule 2** (sensitivity routing enforced, never bypassed): PII documents route to the local embedding lane live (bge-m3), never cloud; Collections API rejects `pii`+`redact` at creation time specifically because that combination would let effective routing sensitivity silently drop to `internal`.
- **Rule 4** (retrieved/tool content is untrusted): query generation wraps retrieved chunks in an explicit `<untrusted_context>` block with an instruction to ignore embedded commands, never concatenated raw into the prompt.
- **Rule 9** (tests accompany code): every new module has unit coverage; every task has a live integration test against real containers.
- **Rule 10** (costs are a feature): embeddings and RAG-answer generation both meter through the gateway client's existing spend-ledger path; the query generation call deliberately uses `reasoning()` (not the cheaper `utility()`) since answer grounding/citation discipline needs the stronger tier.
