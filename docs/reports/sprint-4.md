## Notable issues resolved (symptom → root cause → fix)

- **`psycopg`'s async mode incompatible with Windows' default `ProactorEventLoop`** on the live checkpointer test → set `asyncio.WindowsSelectorEventLoopPolicy()` at module load in that one test file only (Windows/test-infra-specific; production runs under uvicorn on Linux, unaffected).
- **`KillSwitch` passed all 8 unit tests (backed by a fake Redis returning `str`) but failed live**: `redis.asyncio.Redis.get()` returns raw `bytes` unless `decode_responses=True` is set, so `value == "1"` was silently always `False` — a paused agent would have kept running in production. Caught specifically *because* the AC was written to require live proof, not trust mocks. Fixed at the source (`_is_flag_set()` accepts `str | bytes | None`), not just at the one call site that happened to hit it.
- **`LLMClient._call()`/`.embeddings()`/the new `.reasoning_stream()` never forwarded `trace_id`/`agent_id`/`user_id`/`dept_id` to the transport layer** — a genuine pre-existing Sprint-2 defect, confirmed with the user before fixing since it touched code outside 4.3's literal scope. Consequence: every LLM call since Sprint 2 had a `spend_ledger.trace_id` that never actually reached Langfuse's callback, so Langfuse silently minted its own random trace id every time. This directly blocked 4.3's "feedback lands in Langfuse" AC. Verified live before/after via Langfuse's own API (404 → 200). The same gap existed one layer up in `fleet_rag.query.service.answer_query()` for 4.4's RAG chat path and was fixed the same way.
- **Eval-driven finding, not a code bug:** `cs-help-center`'s `pii_policy=redact` (Sprint 3's Presidio + custom TR recognizers) false-positive-flagged generic Turkish nouns ("Kredi", "Kartı") as `[PERSON]`, silently stripping "kredi kartı kabul ediyoruz" from RAG context. Per an explicit user decision, not fixed this sprint — the eval assertion was corrected to check content that survives redaction, and the false-positive is logged as a tracked Sprint-8 KVKK-lane improvement item.
- **Turkish text-matching bug in the eval runner**: `'İ'.lower()` produces `'i' + U+0307 combining dot`, not ASCII `'i'`, breaking naive substring checks — fixed with an NFD-normalize-and-strip-combining-marks helper, caught immediately by the runner's own unit tests.
- **A first attempted fix (`sys.stdout` UTF-8 wrapper at module import time, for a Windows console-encoding crash) broke pytest's own output capture for the entire unit-test session** because the eval test file imports the runner module directly. Fixed by moving the swap into a function called only from `main()`.
- **Two eval-assertion false positives found on the very first live run** (not code bugs): a verb-stem-vs-conjugated-form mismatch (Turkish morphology), and an injection-resistance case that checked for the mere word "şifre" — the model's own *correct refusal* legitimately contains that word. Both fixed by correcting the assertions, not the agent's actual (correct) behavior.
- **E2E: a React controlled-`<input>` DOM/state desync reproduced consistently under `next dev`, absent in a production build** — Playwright's `.fill()` visibly set the DOM value but the Send button stayed disabled because React's state was never actually updated. Root-caused to `next dev`'s fast-refresh instrumentation; running E2E against `next build && next start` instead resolved it with no source change. Documented in `playwright.config.ts` so it isn't rediscovered.

## Deviations / deferrals

- **The RAG chat reply is a single `token` SSE event carrying the complete grounded answer, not real per-token streaming** — the TRD §9 citation-verification retry loop needs the full generated text before it can validate groundedness, so there's no way to stream partial, unverified tokens for a RAG-backed agent. Real token streaming (4.3) and RAG-grounded answers (4.4) are two different delivery shapes for two different guarantees; documented in `chat.py`.
- **Support Copilot does not compile a `core.graph.AgentSpec`** — the chat endpoint calls `fleet_rag.query.service.answer_query()` directly. Support Copilot's Wave-0 spec is pure RAG with zero tools, so it never exercises `core.graph`'s HITL/tool-execution machinery; the first agent to actually need a compiled graph with real tool calls is Sprint 5.
- **`agents.collection_ids` is a plain array column, not a normalized `agent_collections` join table** — an explicit, deliberate simplification for this sprint's single-agent need; noted to become a join table once a second agent or per-collection metadata arrives.
- **`nightly.yml`'s actual GitHub Actions run is unverified** — authored and YAML-validated, but no push/PR triggered it in this environment this session. It also needs `ANTHROPIC_API_KEY`/`OPENAI_API_KEY`/`GEMINI_API_KEY` configured as repo secrets before its `eval`/`e2e` jobs can produce a real grounded answer in CI.
- **`PUT /v1/admin/agents/global/read-only` requires `MANAGE_PLATFORM`**, which — per the pre-existing Sprint-3 role-gap (no seeded Keycloak user holds the exact `platform_admin` role string) — can't be exercised live through the real HTTP API; its enforcement is proven at the unit/graph level instead. Same pre-existing gap as Collections/Models admin, not newly introduced.
- **Real per-agent `max_context_tokens`/RAG caps are read from `AgentQueryConfig` defaults**, not wired end-to-end from the `agents` table row into the chat path's RAG config yet.

## Cross-cutting rules honored

- **Rule 1** (LLM calls only via the gateway client): `core.graph`'s `call_model` and the RAG chat path both go through `core.llm.client.LLMClient`; no provider SDK anywhere new.
- **Rule 2** (sensitivity routing enforced): `_assert_agent_may_read_its_collections()` blocks an agent from retrieving from a collection above its own sensitivity level, before any retrieval happens.
- **Rule 4** (retrieved/tool content is untrusted): `core.guardrails.wrap_untrusted` is now the single shared implementation (promoted out of `fleet_rag`, which imports it rather than keeping a private copy).
- **Rule 6** (cross-cutting middleware never special-cased): every agent compiled through `core.graph` gets the killswitch/guardrail/HITL/citation nodes uniformly — Support Copilot's RAG path is the one deliberate, documented exception, and it's exception because it doesn't use `core.graph` at all, not because the graph was bypassed for it.
- **Rule 9** (tests accompany code): every new module has unit coverage; every task has live verification against real infrastructure (Postgres checkpointer, Redis kill switch, real SSE stream, real Langfuse scoring, real Keycloak browser login).
- **Rule 10** (costs are a feature): the RAG chat path's generation call uses `reasoning()` (not `utility()`) for the same grounding-discipline reason established in Sprint 3; the plain chat passthrough's real-time streaming is deliberately still `reasoning()` since Support Copilot's Wave-0 spec is the only agent live in this sprint and general chat is a generation call-site.
