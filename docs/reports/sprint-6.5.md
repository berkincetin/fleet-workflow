## Notable issues resolved (symptom → root cause → fix)

- **`n8n update:workflow --all --active=true` doesn't take effect on a running instance** — n8n's own CLI prints this warning; discovered only by then testing the invoice webhook and getting a workflow-execution failure. Fixed by adding a restart step to the `make n8n-import` target.
- **Invoice webhook failed with a stale service-key 401, then a stale n8n-REST-API-key auth error** — both API keys already present in this machine's `.env` were issued against a since-reset `api_keys` table / a since-recreated n8n instance. Fixed the Fleet-issued key by minting a fresh one directly against the DB and updating `.env`; the n8n-issued key needs a fresh UI-only mint from the user (flagged OPEN, not blocking — the `auth_error` path it exercises was confirmed working correctly).
- **`n8n-main`'s port comment claimed loopback-only while the binding was actually open on all interfaces** — a stale Sprint-6 comment not matched by the actual compose binding. Corrected the binding itself (not just the comment) as part of 6.5.4.

## Deviations / deferrals

- **Playwright `make e2e` and a full manual browser walkthrough were not run this session** — `make e2e` needs the web app built/started in production mode alongside the full stack, which fell outside this verification pass; the manual home→automations→examples→admin click-through by role is the one remaining item from task 6.5.10. Recommend running both before considering the sprint fully closed end-to-end from a human's perspective.
- **`POST /v1/invoice-agent/runs` (and therefore the invoice-intake webhook's actual extraction step) hits a pre-existing, out-of-scope Windows event-loop gap** (`psycopg.InterfaceError: Cannot use the 'ProactorEventLoop'`) when the Fleet API is run as a bare `uvicorn` process rather than through pytest's fixture-applied `WindowsSelectorEventLoopPolicy`. Confirmed via direct testing that this reproduces identically on the pre-existing endpoint with zero involvement from this sprint's new `workflows.py` proxy — not fixed here, flagged for the user's decision (an explicit event-loop-policy fix belongs in `fleet_api`'s own entrypoint, is Windows-dev-environment-specific, and doesn't affect a Linux/uvicorn production deployment).
- **Recurrence of the known Sprint-1/2/3/6 realm-vs-`rbac.py` role-string gap** (seeded Keycloak roles `admin`/`user` vs. `rbac.py`'s expected `platform_admin`/`member`) blocked live-testing several `manage_platform`-gated paths (global read-only GET, model add) as a real logged-in user; worked around via direct-DB key issuance, same pattern every prior sprint report since Sprint 3 has used. Recommend fixing directly next time it blocks something un-workaroundable, per Sprint 6's own note.
- **Examples-gallery payload storage is deliberately untyped JSON**, mirroring whatever shape each agent's `evals/runner.py` dataclass already expects, rather than normalized columns — avoids a new migration every time an agent's case schema changes; `routers/examples.py` validates only a minimal required-field subset, not the full per-agent contract.
