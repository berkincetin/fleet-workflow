## Notable issues resolved (symptom → root cause → fix)

- **`RuntimeError: Event loop is closed` in `test_auth_rbac.py`, newly surfaced by 7.1a's change** — `fleet_api.db`'s engine is cached process-wide (correct for a real server's single event loop), but Starlette's bare `TestClient(app)` opens a *new* event loop on every call when not used as a context manager, confirmed by reading `TestClient._portal_factory`'s source directly rather than guessing. Fixed with a `reset_engine_cache()` test-only hook plus, for multi-call test functions, switching to `with TestClient(app) as client:` (Starlette's documented fix for exactly this — one portal per `with` block).
- **`GroupingError: column "spend_ledger.ts" must appear in the GROUP BY clause`** on the cost dashboard's burn-down query — `func.date_trunc("day", ...)` was called three separate times across `select()`/`group_by()`/`order_by()`, so SQLAlchemy compiled three distinct bound parameters Postgres couldn't prove were identical. Fixed by reusing one expression object across all three clauses.
- **Assumed Alertmanager supported `${VAR}` env-var expansion in its config file — it doesn't**, and separately refuses to start on a truly empty `slack_configs.api_url` (`"unsupported scheme for URL"`), which would have broken `make dev` for anyone without a real Slack webhook. Both facts were established by running the real v0.28.0 binary, not by assuming. Fixed with a `sed`-substituted config template defaulting to a syntactically-valid-but-inert placeholder.
- **Grafana dashboards silently referenced `"uid": "Prometheus"` (the datasource's *name*) instead of a real uid** — provisioning succeeded with zero errors in the logs (Grafana doesn't fail-fast on a dangling datasource reference, it just renders broken panels), so this would have shipped invisibly without directly querying the dashboard JSON and comparing against the real datasource uid. Fixed by giving `datasources.yml` explicit `uid:` fields and keeping the comparison as a permanent regression test.

## Deviations / deferrals

- **7.3 (admin system-health screen)** stayed [DEFERRABLE], per the plan.
- **Queue-depth and cost-anomaly gauges are computed at scrape time** (a DB query + a Redis `ZCARD` per ~15s Prometheus poll) rather than maintained incrementally — simplest version that proves the pattern; revisit only if scrape load ever becomes a real problem.
- **`amtool`/`promtool`-based tests shell out to `docker run` directly** rather than using `testcontainers` — deliberate, since these are one-shot CLI invocations against a static config file, not long-running services needing lifecycle management.

## Cross-cutting rules honored

- **Rule 2** (sensitivity routing never bypassed): untouched this sprint — no new LLM call-sites.
- **Rule 6** (cross-cutting middleware never special-cased): the new `RequestMetricsMiddleware` wraps `RateLimitMiddleware` deliberately (so a 429 is still counted), added the same way as every existing middleware in `app.py`; new routers use the same `require_permission`/`get_session` dependency pattern as every prior admin router.
- **Rule 7** (migrations only via Alembic): no new migrations this sprint — every new admin feature reads/writes tables that already existed (`roles`, `budgets`, `spend_ledger`, `audit_log`).
- **Rule 9** (tests accompany code): every new module has unit and/or integration coverage; infra config (Prometheus rules, Alertmanager routing, Grafana dashboards) is tested against the real binaries, not just parsed as YAML/JSON.
- **Rule 10** (i18n): every new user-facing string went through `messages/tr.json` (written first) + `en.json`.
